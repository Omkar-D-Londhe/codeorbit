## 1. Executive Summary & Final Verdict

### Final Verdict: **CONDITIONAL PASS — Limited Release Only**

CodeOrbit is functionally mature, pedagogically rich, and demonstrably safe for core release as a web-development learning environment (specifically HTML, CSS, JavaScript, Bootstrap, and Python curricula). The baseline verification pipeline passes with 100% success across TypeScript, ESLint, Vitest, and production build. All sensitive credentials are confirmed absent from client code and bundles. Affirmative consent gates for external integrations (W3C Nu Validator and Gemini AI hints) function properly, and sandboxed preview iframes protect the host application from learner code.

However, an unconditional `PASS` cannot be granted due to two **High-severity** capability limitations and two **Medium-severity** discrepancies between Pass 2 documentation claims and actual runtime code:

1. **Angular Reactive Preview Inactive (P3-H01 — High):** In `src/pages/Practice.tsx`, the `SandboxedPreview` component is invoked with default static sandboxing (`mode="static"`), enforcing `sandbox=""` (no scripts allowed). While the Angular challenge source-code validators execute and grade solutions accurately, the live preview frame cannot execute the interactive `<script>` tags generated by the Angular runner. Reactive interactions (signals, counter buttons, two-way bindings) do not run in the preview pane.
2. **Multiplayer Transport Scope Discrepancy (P3-H02 — High):** Feature O-07 is documented in Pass 2 as "Real cross-device WebRTC multiplayer." In reality, `src/core/multiplayer/peerRace.ts` implements communication exclusively via `BroadcastChannel` (cross-tab within the same browser instance) and an in-memory event bus. There is no `RTCPeerConnection` or `RTCDataChannel` logic in the client runtime, and the standalone WebSocket signalling server (`server/signalling/relay.ts`) is never invoked by `peerRace.ts`. Multiplayer works across tabs in the same browser, but not across distinct physical devices or networks.
3. **AI Hints Server-Side Rate Limiting Missing (P3-M04 — Medium):** Rate limiting (5/hr, 20/day) is enforced purely in client `localStorage`. The Node proxy (`server/proxy/ai-hints.ts`) has no rate-limiting middleware, allowing unrestricted upstream Gemini quota consumption if the proxy endpoint is invoked directly.
4. **Unenforced Worker Memory Ceiling (P3-M03 — Medium):** Pass 2 reported a "128MB heap ceiling" for Java and C++ workers. No explicit memory cap is configured in the Web Worker instantiation or browser flags. Execution watchdog timeouts and worker termination work as intended, but memory is unbounded.

## 6. Phase C — Feature-Specific Adversarial Audits

### O-04: In-Browser Java & C++ Execution
- **Implementation:** `src/tracks/java/runnerWorker.ts`, `src/tracks/cpp/runnerWorker.ts`, `runner.ts`.
- **Strengths:** 
  - Line-by-line structural AST evaluators handle standard expressions, variable assignment, loops, string concatenation, and `System.out.println` / `cout <<`.
  - Infinite loops (`while(true)`) are intercepted via regex patterns and timeout guards.
  - Workers can be terminated and restarted cleanly without leaking application state.
  - Dangerous primitives (`ProcessBuilder`, `Runtime.getRuntime()`, `system()`, `fork()`) are blocked upfront.
- **Deficiencies:**
  - **Memory Ceiling Unverified (P3-M03):** The Pass 2 report claimed a "128MB heap ceiling." Inspection of `runnerWorker.ts` and `runner.ts` reveals no memory allocation cap or `--max-old-space-size` flag. While worker termination prevents UI freezing, memory is not capped.
  - **Compilation Pedagogics:** Code is interpreted via structural regex/AST traversal rather than real WebAssembly bytecode compilation. The application UI must maintain honest labeling that this is a learning evaluator, not a full JVM or Clang compiler.

### O-05: Angular Interactive Practice Lab
- **Implementation:** `src/tracks/angular/` (`challenges.ts`, `runner.ts`, `validators/index.ts`).
- **Strengths:**
  - 12 comprehensive challenges covering signals, bindings, pipes, services, control flow (`@if`, `@for`), and routing stubs.
  - 7 robust structural AST validators accurately grade student code submissions.
- **Deficiencies:**
  - **Live Reactive Preview Broken (P3-H01):** `Practice.tsx` instantiates `SandboxedPreview` at line 1119 without passing `mode="script"`. It defaults to static mode, rendering inside an iframe with `sandbox=""` (disallowing all script execution). The `<script>` tags emitted by `AngularRunner.run()` are inert. Clicking reactive buttons or counters in the preview produces zero response.

### O-06: AI-Powered Hint Expansion
- **Implementation:** `server/proxy/ai-hints.ts` (server), `src/core/services/aiHints.ts` (client).
- **Strengths:**
  - Zero API keys in client bundles. `GEMINI_API_KEY` is referenced solely on the server via `process.env`.
  - Affirmative consent required: no prompts or code snippets leave the client until `ai-hints-consent` is accepted in `localStorage`.
  - Offline resilience: when offline or unconfigured, the system gracefully falls back to deterministic curriculum hints.
- **Deficiencies:**
  - **Client-Side-Only Rate Limiting (P3-M04):** Rate limiting (5/hr, 20/day) is tracked only in browser `localStorage`. Direct curl or POST requests to the proxy bypass all limits.
  - **Permissive CORS (P3-L02):** `server/proxy/ai-hints.ts` sets `Access-Control-Allow-Origin: *`.

### O-07: Real Cross-Device Multiplayer Races
- **Implementation:** `server/signalling/relay.ts`, `src/core/multiplayer/peerRace.ts`, `RaceHud.tsx`.
- **Strengths:**
  - SHA-256 solution checksum calculation prevents plain copy-paste exploits.
  - 15-second disconnect grace timer with HUD notification.
  - **Zero bots verified:** Opponent disconnection transitions cleanly to `opponent-disconnected`; no simulated bots are injected.
- **Deficiencies:**
  - **Cross-Device WebRTC Incomplete (P3-H02):** Pass 2 reported WebRTC DataChannel as the primary transport. In the actual codebase, `peerRace.ts` only implements `BroadcastChannel` and a local in-memory event bus. There is no `RTCPeerConnection` or SDP exchange logic in the client. The WebSocket signalling server exists as a standalone file but is never imported or called by the race engine. Multiplayer is strictly cross-tab within the same browser origin.

### O-14: Live W3C Nu HTML Validation
- **Implementation:** `src/core/services/w3cValidator.ts`.
- **Strengths:**
  - Explicit affirmative consent required before sending any HTML to `https://validator.w3.org/nu/`.
  - Diagnostics are mapped directly to CodeMirror gutter annotations.
  - Reliable local fallback: if network request fails or times out (8,000ms), local AST validation takes over, transparently labeled `source: 'local-fallback'`.
- **Deficiencies:**
  - **In-Memory Rate Cooldown (P3-L03):** Cooldown is stored in module state (`lastValidationTime`) and resets upon browser refresh.

Inspection of `index.html` CSP meta tag:
```text
default-src 'self';
script-src 'self' 'unsafe-inline' 'wasm-unsafe-eval' blob:;
worker-src 'self' blob:;
style-src 'self' 'unsafe-inline';
img-src 'self' data: blob: https:;
font-src 'self' data:;
connect-src 'self' https://validator.w3.org https://generativelanguage.googleapis.com blob:;
frame-src 'self' blob: data:;
object-src 'none';
```

- **Evaluation:** Strict `object-src 'none'` prevents Flash/plugin exploits. `connect-src` strictly whitelists W3C and Google APIs.
- **Limitation (P3-M02):** `script-src 'unsafe-inline'` is present. Required for inline CodeMirror theme scripts and service-worker bootstrap, but reduces CSP strictness. Sandboxed iframes mitigate risk from learner code.

- JavaScript preview: Uses `sandbox="allow-scripts"` (strictly omitting `allow-same-origin`), preventing access to host `localStorage` or parent cookies.

- Server-side secrets (`GEMINI_API_KEY`) isolated strictly to Node runtime environment.
