# Decisions made in this build (D-1xx)

Original locked decisions remain in `docs/reference/DECISIONS.md`. Additions/clarifications:

| ID | Decision | Why |
|---|---|---|
| D-101 | **Greenfield build.** No CodeOrbit repository was supplied (the second upload held lab-submission PDFs only), so the project was created from scratch in `codeorbit/`. | Cannot preserve code that was not provided. |
| D-102 | Stack: React + TS + Vite + React Router + custom CSS + versioned localStorage. Only extra runtime deps: three `@fontsource-variable/*` font packages (self-hosted, no CDN). | Preferred stack in the brief; fonts give typographic identity without network calls. |
| D-103 | 12 topics / 8 groups, one lesson + 3-question quiz + 1 challenge each. Prerequisite edges are declared explicitly; a test asserts curriculum order ≠ a dependency chain and that every edge points to an earlier topic. | Real relationships only. |
| D-104 | Orbit display mode is derived from geometry (min node spacing 56px; label-box collisions), producing `arch` ≥ ~900px, `arch-compact` ~640–899px, `carousel` below. Phones use the carousel. | Brief: try compact arch first, fall back if targets are tiny; here 360–430px give < 56px spacing. |
| D-105 | Nodes at equal **arc length** on a half-ellipse; edges as quadratic curves bowed toward the arch interior. | Even spacing; connectors never cross the rim. |
| D-106 | Challenge validation = declarative `Rule` objects evaluated on a `DOMParser` document (detached, never attached). | Deterministic, testable, no `eval`. |
| D-107 | Preview = `<iframe sandbox="" srcdoc>` plus a CSP meta (`default-src 'none'; img-src data:; style-src 'unsafe-inline'`). Remote images are therefore blocked by design; challenges use `data:` images. | Defence in depth; no scripts, no same-origin, no forms/popups. |
| D-108 | Progress (D-018 in the original numbering): lesson = learner marks complete; quiz passed = best ≥ 2/3; practice = every requirement passes in a Check; *completed* = all three; *mastered* = completed + perfect quiz best + practice finished before any solution reveal. Opening a page is **not** progress. | Evidence-based, no false progress. |
| D-109 | Quick quiz allows “Skip question” (counts as unanswered) and “Check answer” is disabled until an option is chosen. Answers are final once checked. In-flight sessions persist. | Truthful scoring + resume. |
| D-110 | “Saved” text appears only after a successful `setItem` (`saveStatus.at ≥ note.updatedAt`); storage failure shows a warning. | No fake confirmations. |
| D-111 | Editor is a plain `<textarea>` with a line gutter; no Tab capture; syntax highlighting only in read-only code blocks. | Avoid keyboard traps and fragile overlay alignment. |
| D-112 | **Not implemented** (blueprint “when in scope”): Achievements, Daily Challenge, Mastery graph route, streaks. No routes or controls exist for them. | Avoid fake working routes; budget went to the core journey. |
| D-113 | Quiz option order is rotated by a stable hash of the question ID so the correct answer is not always in the same slot; deterministic across loads. | Content quality without randomness that would break resume. |
| D-114 | **Storage Schema v2 & Migrations**: Bumps `SCHEMA_VERSION` from 1 to 2; adds `settings`, `activity`, `activityDays`, `dailyDone`, `dailyAssigned`, and `streakBest`. Migration `migrateV1toV2` safely preserves all v1 fields and reference-era activity without data loss. | Clean schema evolution while keeping 100% backward compatibility. |
| D-115 | **Debounced Persistence & Flush**: 300ms write debounce protects storage cycles during typing; immediate synchronous flush on `pagehide` and `visibilitychange` (`hidden`) ensures no data loss on tab close; cross-tab `storage` listener synchronizes state. | High-performance persistence without losing in-flight learner progress. |
| D-116 | **Storage Quota Guard**: Soft budget of 4 MiB with warning threshold at 80% (3.2 MiB). In-app warnings surfaced in Shell status note and Settings page rather than crashing or throwing unhandled errors. | Graceful degradation under storage constraints (FC-07/FC-08). |
| D-117 | **Pluggable Clock & Meaningful Activity**: `ClockProvider` and `useClock()` allow deterministic time injection for tests; activity events logged only for substantive actions (lesson completion, quiz finish, passing challenge check) with rule table. | Prevents activity spam and enables rigorous time-travel testing. |
| D-118 | **Settings & Data Management (FC-07)**: Full settings page with real labelled form controls (`#user-name-input`, `#pace-select`, radio theme selectors, toggle switches), storage quota meter, JSON backup export/import with preview dialog, and typed `RESET` confirmation modal. | Accessible user autonomy and transparent data ownership. |
| D-119 | Language-neutral TrackRegistry and TrackModule contract (`src/core/content/`). HTML wraps existing data without moving files; planned tracks registered as `planned`. Pages query registry via `useTrack()`. | Removes single-technology coupling while preserving all working data and behavior. |
| D-120 | Added devDependencies `vitest-axe` (0.1.0) and `@playwright/test` (1.58.2). Zero runtime dependencies added. | Required for automated axe-core accessibility checks and end-to-end browser smoke verification. |
| D-121 | **Owner Decision O-16 confirmed (2026-10-26)**: Prerequisites are advisory. Never block or redirect `/lesson`, `/quiz`, or `/practice` routes because prerequisites are incomplete. | Owner locked decision. |
| D-122 | **Stage 01 Deviations Recorded**: (1) Stage branch named `stage-01-baseline-lock-and-neutral-core` (treating §7 step 2 `stage-01-baseline-neutral-core` as typo). (2) `vite.config.ts` `test.exclude` updated to exclude `e2e/**` and `docs/**` (including `docs/antigravity/reference/engagement.test.tsx`) while preserving Vitest default exclusions. (3) `eslint.config.js` `no-restricted-syntax` scope extended to include `src/lib/**` in addition to `pages`, `components`, `core`. (4) ESLint ignore added for `docs/**` and `docs/antigravity/reference/**`. | Strict conformance with Stage 01 instructions and cleanliness. |
| D-123 | **Atmosphere Layer Architecture**: Fixed, `aria-hidden="true"`, `pointer-events: none` background container sitting at `z-index: 0` behind `<main>` (`position: relative; z-index: 1`). Nebula rendered on Home and Track only; Constellation grid active globally; Cursor glow and ambient particles opt-in via Settings. All layers completely absent in high-contrast mode. | Restrained celestial aesthetics without compromising accessibility, readability, or interaction. |
| D-124 | **Deterministic Starfield Backdrop**: Pure, seeded `starPositions(seed, density)` capped at $\le 150$ dots and $\le 12$ twinkling dots. Rendered via SVG vector circles, completely absent in high contrast, and twinkle animation suppressed when motion is reduced. | Deterministic backdrop for constellation orbit (Stage 10) and UI gallery specimen. |
| D-125 | **Motion Preference & Reduced Motion Precedence**: `Settings.motion` supports `system` (follows OS `prefers-reduced-motion`), `reduced` (suppresses animations/transitions), and `full` (explicit learner choice). Mirrored in CSS via `html[data-motion='reduce']` and `html[data-motion='reduced']`. | Absolute user control over motion sensitivity. |
| D-126 | **Decision Gate O-01 Proceeded with CodeMirror 6 (P-01)**: Implemented `CodeMirrorEditorAdapter` behind language-neutral `EditorAdapter` contract, with dynamic `import()` chunking (`codemirrorAdapter-*.js`, 172 kB gzip), while maintaining `PlainTextEditorAdapter` as zero-runtime fallback and test adapter. | Lightweight syntax highlighting and tag completion without bundle bloat; preserves plain fallback resilience. |
| D-127 | **Split-View Resizer (6.2, FC-18)**: Accessible `role="separator"` splitter dividing Practice editor and preview with pointer drag and keyboard controls (Arrow keys $\pm 2\%$, Home 25%, End 75%, Enter/Space/r reset to 50%). | D-128 | **Accessible Editor Keyboard & Fullscreen Platform**: By default `tabCapturesFocus: false` ensuring Tab navigates outside the editor; learners may opt into `tabCapturesFocus: true` in Settings with clear instructions to press Esc then Tab to exit. | D-129 | **Multi-File Practice Workspace, Device Frames, Diff Gating, A11y Linter & Soft Difficulty**: Multi-file tab UI rendered conditionally when challenge contains > 1 file; preview document stitches CSS into `<style data-filename="...">` with `</style>` breakout defense; Myers LCS line diff capped at 2000 lines and strictly gated behind solution reveal; DOMParser-based accessibility linter checks common mistakes (missing alt, unlabelled inputs, empty headings, ID duplicates, hierarchy skips) with explicit non-WCAG disclaimer; snippet library inserts accessible templates at cursor; challenge difficulty progression is advisory only (O-16) and never blocks exploration. | Adheres to L-06, L-11, L-12, L-17, L-21, O-16, and FC-07. |
| D-130 | **Feedback & Deterministic Code Coach Framework (Schema v3)**: Source-position mapping resolves 1-based line/column offsets for HTML rule violations; failed requirements map to `EditorDiagnostic` markers in the editor; progress bar with `role="progressbar"` reflects met/total progress; requirement rows group into Met/Not met with animated state transitions ($\le 160$ ms, disabled under reduced motion) and expandable `<details>` explanations; attempt history persists across reloads under Schema v3 capped at 20 checks; Code Coach persona strictly enforces L-05 copy rules (labeled 'Code Coach · rule-based, specific to this challenge', zero 'AI' or code review claims). | Adheres to L-05, FC-30, FC-32, and WCAG AA non-motion criteria. |
